# 评分榜网页体验

评分榜首页、单榜筛选、对象详情、评分/回复/点赞/编辑/删除和对象创建均由 `/rating/` 提供。保留原 App 的粉彩榜单头、蓝色分数、橙红摘要和黄色星星，新增顶部目录与校园位置、类型、月份、单品信息。

## 视觉基准

按虎扑[榜单页](https://m.hupu.com/score-list/common_first/2103947)和[评分详情](https://m.hupu.com/score-item/common_second/3141509)的实际布局调整。首页沿用原 App `rate_overview_card.dart` 的粉彩头部、三箭头和独立条目；完整榜单采用方形封面、右侧评分、下方摘要；详情采用圆角内容分组、浅蓝评分面板、星级入口和底部输入栏。

颜色以原 App `rate_decorations.dart`、`app_theme.dart` 为准：主蓝 `#0092FF`、浅色摘要 `#FF5A3D`、星色 `#F5A623`，榜单色相仍按 ID 分配。深色首页分数为 `#00A8C2`。评分星星按真实均分填充，没有评分时显示“暂无评分”；接口没有星级分布，因此不展示分布图。详情点击星级可预选分数，已有评价会进入编辑。

保留原 App 榜单标题右侧的举牌小鸭和空列表插画，素材无损转为 WebP。对象列表、详情和点图预览继续读取原 `coverUrl`；首页榜单卡补齐封面背景图、渐变遮罩和白字，榜单详情保留封面与小鸭。无封面或加载失败时恢复粉彩头部，不显示无意义的标题文字占位块。榜单 `coverUrl` 是旧 App 模型预留能力，目前后端榜单实体和表没有该字段，本次不新增数据库字段，也不更改旧 JSON 契约。

榜单仅按校区筛选，不再提供楼栋选项。校区采用横向文字标签，摄影月份采用横向标签，排序直接点选综合/得分/人数；旧链接的 `building` 参数不参与请求，后续筛选操作会清除它。已验证校区 0、切换校区、全部校区、月份空态、旧链接兼容以及 320px 明暗布局，榜单页面无下拉框和横向溢出。

筛选区采用轻底色搜索框、蓝字胶囊校区选中态与紧凑分段排序；搜索操作去掉内嵌卡片，数量改为次要文字并靠近列表。搜索保留回车提交、16px 输入字号和聚焦描边；清空按钮只删除关键词，保留校区、排序等其他条件并恢复输入焦点。搜索、校区、排序按钮均保留至少 44px 点击高度。复用现有 Motion 的无回弹 spring 移动选中底板，校区滚动容器使用 `layoutScroll`，减少动态时使用静态底板；不阻塞连续点选。榜单排序样式单独限定，评论排序不受影响。横条右端渐隐提示可滚动，恢复筛选时仅横向显露当前校区，重置同时回到“全部校区”。月份和类型标签仅在筛选区统一圆角，不影响对象详情与创建页。浏览器复验覆盖 390px/320px 明暗、连续反向切换、末尾校区底板对齐、搜索与清空保留校区 0 和排序、重置与无横向溢出；此前摄影附加筛选验收仍保留。

详情页进一步统一封面、导航、评分、单品和评论的圆角与间距，以细边框和轻渐变取代大块纯色与粗分隔。总分、满分标记和参与人数分层排列；快捷星级保留 44×44px 点击区域，窄屏标签换行，按下提供反馈。顶部和底栏使用轻透材质，降低透明度或增强对比度时改用实色，减少动态时取消缩放。评论排序改为“最新 / 最热”分段按钮，仍发送 `createTime` / `likeCount`，没有更改 JSON、评分、价格和旧评价编辑语义。390px 明暗、320px 长标题、星级预选、原图预览、评论切换和旧 7 分编辑均已通过浏览器演示复验；10 项评分回归、Astro 检查和生产构建通过。地图按钮仅验证演示入口，真实高德唤起仍需真机联调。

## 与 App 的连接

仅新版 App 的 `northwardRating` WebMessageListener 可访问真实数据。网页通过受限桥调用现有认证请求、相册 OSS 上传、用户主页和高德导航；token、刷新凭据、OSS 临时凭据都不交给网页。网页需随配套 App 和后端一起发布，普通浏览器会提示在 App 中打开。

消息包含 `id/action/route/routeRevision`，回包 `id/result` 或 `id/error`。每次哈希导航先通知原生。旧路由上传和旧登录会话被取消；列表组件按请求版本丢弃过期结果。会话变化显示整页刷新入口。网页返回保留筛选，筛选修改不堆积历史。

## 旧数据兼容

兼容范围为旧前后端的 JSON 输入输出，允许后端升级。旧请求原样有效，不要求新增校区等字段；旧响应缺少扩展字段时网页仍可读取；新响应保留旧字段的名称、类型和 `data.records` 分页结构，旧 App 忽略新增字段。网页详情使用配套后端新增的接口，发布仍遵循后端先于网页/App 的顺序。

兼容以现有表与接口契约为准：继续使用原榜单、对象、评价和回复 ID；保留正文、图片、分数、人数、点赞、回复关系及匿名状态。迁移只增加列和索引，不删除、重建、重新编号或自动重分类旧记录。

旧榜单保留 `general`，缺少类型的旧响应也按综合榜展示；旧对象不要求补齐校区、标签、月份或单品。未填校区的数据仍在默认列表和“全部校区”内，只有用户选择具体校区时才按实际字段过滤，不猜测校区。

编辑评价时，未修改的正文和图片字段不回传，由后端保留原值，避免重写旧正文空白或把历史图片当作新上传再次校验。图片发生增删时明确提交数组，全部删除提交 `[]`；保留的旧图由后端按该评价已有引用识别，新图仍校验归属。旧的 1–10 整数分数（包括 7 分）保持原值，只有用户主动选星才改分。匿名头像不展示，`show_rate_badge=false` 时不显示分数。

`npm run test:rating` 覆盖 10 项组件渲染与编辑请求回归：旧榜单、缺失/空元数据、空统计、原 ID 与统计、历史图片、匿名、奇数分、正文换行及附件省略/清空语义。开发模式可用 `/rating/?preview=1&legacy=1#/ranks/6` 查看合成旧数据，或在 `/ranks/1` 检查同榜新旧对象共存。这些样例不来自生产，且不进入生产构建。

浏览器已验证旧榜单详情、历史评价编辑保存、图片与 7 分保留，以及全部校区→具体校区→全部校区后旧对象重新出现。尚未读取生产样本或执行真实数据库迁移；上线前仍需以数据副本核对迁移前后记录数量、ID、关系与评分统计。

## 本地预览与验证

运行 `npm ci`、`npm run dev -- --host 127.0.0.1 --port 4321`，打开 `http://127.0.0.1:4321/rating/?preview=1`。仅开发构建加载内存演示数据；发布、上传和导航模拟均不触及线上。生产构建不包含 preview transport 或切换明暗按钮。

开发对象图复用原 App 表情和仓库旧截图中的食品图片，正式数据不使用这些示例替代原图。用 `/rating/?preview=1&covers=1#/` 可检查榜单封面分支。恢复素材后已通过 10 项评分回归、Astro 检查和生产构建；浏览器验证对象缩略图、点开大图、首页榜单封面、空态插画以及 390px/320px 明暗布局，未出现横向溢出。

已通过 Astro 类型检查和生产构建。浏览器验收覆盖目录、校区筛选、详情单品及未知价格、匿名评分、编辑、删除后重评、回复、创建美食对象及审核成功页、摄影月份和各类型标签、返回保留筛选。手机 390px 暗色和 320px 布局单独检查。

2026-11-10 视觉调整后重新通过 `npm run build` 和 `npx astro check`（0 错误、0 警告，4 条既有提示）。本次浏览器复验覆盖 390px 首页/完整榜单/详情/评分弹层、320px 暗色详情和摄影月份空态、排序、评分预选及演示发布；320px 页面未出现横向溢出。截图来自开发演示模式，不能作为生产数据或真实 WebView 联调证据。

网页演示验证不等于真实后端端到端联调；真机 WebView、相册/OSS、高德唤起和数据库迁移仍需发版环境验收。本轮按用户要求没有做真机测试，也没有部署。

## 发布顺序

1. 执行后端加列迁移；新增摄影、运动、自习、蹭课榜的独立种子脚本可重复运行。
2. 发布后端和 Admin；旧榜单默认为 general，需要管理员明确将美食榜设为 food 并补齐地点/单品。不会猜旧数据。
3. 发布官网 `/rating/`。
4. 发布 App；保留旧数据库字段，旧版 App 继续兼容。

详情和迁移见后端 `docs/rating-web-experience.md`、`docs/migrations/add_rating_web_experience.sql`。回滚网页/App 时保留新增列。
