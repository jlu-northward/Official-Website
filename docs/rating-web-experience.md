# 评分榜网页体验

评分榜首页、单榜筛选、对象详情、评分/回复/点赞/编辑/删除和对象创建均由 `/rating/` 提供。保留粉彩卡片、蓝色分数和浮动操作入口，新增顶部目录与校园位置、类型、月份、单品信息。

## 与 App 的连接

仅新版 App 的 `northwardRating` WebMessageListener 可访问真实数据。网页通过受限桥调用现有认证请求、相册 OSS 上传、用户主页和高德导航；token、刷新凭据、OSS 临时凭据都不交给网页。网页需随配套 App 和后端一起发布，普通浏览器会提示在 App 中打开。

消息包含 `id/action/route/routeRevision`，回包 `id/result` 或 `id/error`。每次哈希导航先通知原生。旧路由上传和旧登录会话被取消；列表组件按请求版本丢弃过期结果。会话变化显示整页刷新入口。网页返回保留筛选，筛选修改不堆积历史。

## 本地预览与验证

运行 `npm ci`、`npm run dev -- --host 127.0.0.1 --port 4321`，打开 `http://127.0.0.1:4321/rating/?preview=1`。仅开发构建加载内存演示数据；发布、上传和导航模拟均不触及线上。生产构建不包含 preview transport 或切换明暗按钮。

已通过 Astro 类型检查和生产构建。浏览器验收覆盖目录、校区/楼栋筛选、详情单品及未知价格、匿名评分、编辑、删除后重评、回复、创建美食对象及审核成功页、摄影月份和各类型标签、返回保留筛选。手机 390px 暗色和 320px 布局单独检查。

网页演示验证不等于真实后端端到端联调；真机 WebView、相册/OSS、高德唤起和数据库迁移仍需发版环境验收。本轮按用户要求没有做真机测试，也没有部署。

## 发布顺序

1. 执行后端加列迁移；新增摄影、运动、自习、蹭课榜的独立种子脚本可重复运行。
2. 发布后端和 Admin；旧榜单默认为 general，需要管理员明确将美食榜设为 food 并补齐地点/单品。不会猜旧数据。
3. 发布官网 `/rating/`。
4. 发布 App；保留旧数据库字段，旧版 App 继续兼容。

详情和迁移见后端 `docs/rating-web-experience.md`、`docs/migrations/add_rating_web_experience.sql`。回滚网页/App 时保留新增列。
